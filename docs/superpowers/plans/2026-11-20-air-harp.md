# Air Harp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local web page that tracks both hands through the Mac webcam. Pinching with both hands draws "strings", sweeping the index finger across a string plucks it with a synthesized sound and a visible vibration, and holding an open palm over a string deletes it.

**Architecture:**
- **Static ES modules.** No build step and no npm dependencies.
- **Pure logic, testable on Linux.** Geometry, pose classification, the gesture state machine, pitch mapping, the string model and the Karplus–Strong synth contain no browser code, and are tested with `node --test`.
- **Browser-only modules, verified by the user on their Mac.** A thin layer (tracker, renderer, audio playback, debug overlay, main loop) wires those parts to MediaPipe, Canvas and Web Audio.
- **Gestures are an event emitter.** The gesture engine reads hand frames plus the current strings and returns events. `main.js` applies the events.

**Tech Stack:**
- Vanilla JS (ES modules)
- `@mediapipe/tasks-vision@0.10.14` HandLandmarker, loaded from the jsDelivr CDN
- Canvas 2D
- Web Audio
- `node:test` on Node 22
- Served with `python3 -m http.server`

**Spec:** `docs/superpowers/specs/2026-11-20-air-harp-design.md`

## Global Constraints

- The page must run in recent desktop Chrome and Safari, served from `localhost`. The camera needs a secure context.
- No build step and no npm dependencies. `package.json` exists only for `"type": "module"` and the `test` script.
- The page opens on a "Click to start" screen. That click creates the AudioContext and requests the camera.
- The camera feed is mirrored (selfie view), full-window, and dimmed. Strings are drawn on a canvas on top.
- All tunable thresholds live in `src/config.js` and nowhere else.
- Coordinates are screen pixels everywhere after `tracker.js`. Landmark x is mirrored as `(1 - x) * width`.
- Shorter strings play higher notes. Pitch snaps to the C major pentatonic scale (pitch classes 0, 2, 4, 7, 9) when `SNAP_TO_SCALE` is true.
- Strings shorter than `MIN_STRING_LENGTH` (60 px) are discarded when released.
- Opening either hand finishes a draw.
- Plucking and deleting are off while a draw is in progress.
- A pinching hand does not pluck, and neither does an open-palm hand.
- A string younger than `DELETE_GRACE_MS` (1000 ms) cannot be deleted.
- The delete hold is about 1 s (`DELETE_HOLD_MS` = 1000). The string shows red as a countdown, and moving away cancels it.
- Visual vibration decays at the same rate as the sound. Higher notes wobble faster. Strings glow when plucked.
- Debug overlay on the `D` key. Landmark recorder on the `R` key, which downloads JSON.
- Pure modules must not touch `window`, `document`, or `AudioContext`.

## Review Focus

1. **A hand leaves the frame mid-draw.** Treat it like opening that hand: after `RELEASE_MS` the last preview line is committed (or discarded if too short). It must never get stuck in drawing mode. Test in Task 4.
2. **Opening your hands to finish a draw.** The fingertips move across the brand-new string. That must not pluck it (`POST_DRAW_MUTE_MS`) and must not start deleting it (grace period). Test in Task 4.
3. **Tracking drops a hand for a frame, and it reappears elsewhere.** The jump from its old position to its new one must not count as a sweep that plucks every string in between. Test in Task 4.
4. **The pinch flickers open for a single frame mid-draw** because of noise near the threshold. That must not commit the string early. The fix is hysteresis plus `RELEASE_MS`. Tests in Task 3 and Task 4.
5. **The window is resized after strings are drawn.** Existing strings keep the pitch they were created with. Frequency is computed once, at creation. Test in Task 5.

### Task 4: Gesture engine

**Files:**
- Create: `src/gestures.js`
- Test: `test/gestures.test.js`

**Interfaces:**
- Consumes: Task 1 geometry, Task 3 `src/hands.js`, `CONFIG`
- Produces:
  - `createGestureEngine(cfg = CONFIG)`, which returns `{ update(frame: Frame, strings: HarpString[]): GestureEvent[], get state(): 'idle'|'drawing' }`
  - The engine only reads `strings`, using `id`, `a`, `b` and `createdAt`. It never mutates them.

Behavior, using `frame.t` as the clock:
- **idle → drawing:** two hands are present and both are pinched. Emit `preview` with the two pinch points, ordered by x, every frame.
- **drawing → idle:** if fewer than two pinched hands have been present for `RELEASE_MS`, emit `previewEnd`. Also emit `create` with the **last preview points** if their distance is at least `MIN_STRING_LENGTH`. Then set `muteUntil = t + POST_DRAW_MUTE_MS`. Frames during the release wait emit no `preview`.
- **Pluck:** only when idle and `t >= muteUntil`. A hand plucks only if it is neither pinched nor open-palm. Its sweep segment runs from its previous index tip (stored per label) to its current one. Skip the hand if it had no previous tip last frame, or if the jump is larger than `MAX_JUMP_PX`.
  - For each string whose segment intersects the sweep and whose last pluck was at least `PLUCK_COOLDOWN_MS` ago, emit a `pluck` event.
  - `velocity = clamp(sweepLength / dt / PLUCK_SPEED_MAX, 0.2, 1)`
  - The previous tips are updated every frame for every hand that is present, in all states. Tips of absent labels are deleted.
- **Delete:** only when idle. For an open-palm hand, find the nearest string with `pointToSegmentDistance(palmCenter, a, b) <= DELETE_RADIUS` and `t - createdAt >= DELETE_GRACE_MS`.
  - When the target is the same as last frame, emit `deleteProgress` with `progress = (t - start) / DELETE_HOLD_MS`. Once progress reaches 1, emit `delete` and clear the target.
  - When the target changes or disappears, emit `deleteProgress` with progress 0 for the old target.
  - Only one target at a time; the first open palm in `hands` order wins.

- [ ] **Step 1: Write the failing tests.** Build frames with `makeHand` at 33 ms steps. `s(id, a, b, createdAt = -10000)` is a string fixture.
  - `draw creates a string`: two `pinch` hands at (100,300) and (500,300) for 3 frames emit `preview`. Then the right hand switches to `point` for 4 frames (≥ 100 ms), which emits `previewEnd` and `create` with a≈(100,300), b≈(500,300).
  - `draw follows hands`: moving the right pinch to (700,300) before releasing makes `create.b` ≈ (700,300).
  - `short draw discarded`: pinches 40 px apart produce `previewEnd` and no `create`.
  - `one-frame flicker doesn't commit` (Review Focus 4): during a draw, one frame where the right hand is `point`, then `pinch` again, produces no `previewEnd`, and the state stays `drawing`.
  - `hand leaving mid-draw commits` (Review Focus 1): during a draw, the right hand is absent for 4 frames. Expect `create` with the last preview points, and the state is `idle`.
  - `no pluck or delete right after draw` (Review Focus 2): after a `create`, append the created string (createdAt = t of create) to `strings`. Then sweep a `point` hand across it within 300 ms and hold an `open` hand on it for 1.2 s. Expect no `pluck` and no `delete` for that id.
  - `pluck`: string from (300,100) to (300,500). A `point` hand moving from x=250 to x=350 at y=300 over one frame emits `pluck` for that id, with velocity in [0.2,1]. Holding still on the string doesn't pluck again.
  - `fast sweep is louder`: a 100 px move in 33 ms gives a higher velocity than a 30 px move in 33 ms.
  - `sweep plucks several strings`: three parallel strings, one sweep across all of them, gives three `pluck` events.
  - `cooldown`: crossing the same string back and forth on consecutive frames 33 ms apart gives 1 pluck. Taken 100 ms apart, it gives 2.
  - `pinching and open hands don't pluck`: the same sweep with `pinch` or `open` hands gives no `pluck`.
  - `reappearing hand doesn't pluck` (Review Focus 3): a `point` at x=250, then a frame with no hands, then a `point` at x=350. No pluck.
  - `teleport doesn't pluck`: a jump of 300 px in one frame. No pluck.
  - `delete after hold`: an `open` hand with its palm center on an old string. `deleteProgress` rises, and `delete` fires on the first frame at or after 1000 ms.
  - `moving away cancels`: after 500 ms, the hand moves 200 px away. Expect `deleteProgress` with progress 0, and no `delete`.
  - `no pluck/delete while drawing`: while two hands are pinched, a third hand is impossible, so instead check that `state` is `drawing` and that strings under the pinch points get no `pluck`.

### Task 5: String model and vibration

**Files:**
- Create: `src/strings.js`
- Test: `test/strings.test.js`

**Interfaces:**
- Consumes: `lengthToFrequency`, `frequencyToColor`, `pitchPosition`, `dist`, `CONFIG`
- Produces:
  - `createString(a, b, now, maxLength, cfg = CONFIG): HarpString`. Ids come from a module-level counter. Frequency and color are computed here, once.
  - `pluckString(str, velocity, now): void`. Sets `pluckedAt` and `velocity`.
  - `displacement(str, u: number, now: number, cfg = CONFIG): number`. Returns the offset in px, perpendicular to the string, at position `u` (0..1).
  - `glow(str, now, cfg = CONFIG): number` returns 0..1.

- [ ] **Step 1: Write the failing tests:**
  - `createString` sets `length = dist(a,b)` and `freq = lengthToFrequency(length, maxLength)`. Ids are unique, and `pluckedAt` is null.
  - **Pitch fixed at creation** (Review Focus 5): a string created with `maxLength` 1000 keeps its `freq` after you call `createString` again with `maxLength` 2000 for another string. Its own `freq` doesn't change.
  - An un-plucked string has displacement 0 everywhere.
  - Displacement is 0 at `u=0` and `u=1` at any time.
  - `|displacement(s, 0.5, t)| <= VIB_AMPLITUDE_PX * velocity` always.
  - Decay: the maximum of |displacement| at u=0.5 over a 1/VIB_HZ_MIN-long window starting 3·DECAY_S after the pluck is under 10% of the same over the window starting at the pluck.
  - A higher `freq` string wobbles faster: count sign changes at u=0.5 over 1 s for the lowest and highest notes. The high note has more.
  - `glow` is 1 at the pluck time and 0 after `GLOW_MS`.
- [ ] **Step 2:** Run `node --test test/strings.test.js`. Expected: FAIL.
- [ ] **Step 3:** Implement. With `dt = (now - pluckedAt)/1000` seconds:

```js
visHz = VIB_HZ_MIN + (VIB_HZ_MAX - VIB_HZ_MIN) * pitchPosition(freq)
displacement = VIB_AMPLITUDE_PX * velocity * exp(-dt / DECAY_S) * sin(PI*u) * sin(2*PI*visHz*dt)
```

- [ ] **Step 4:** Run `node --test`. Expected: all pass.

### Task 6: Karplus–Strong synth

**Files:**
- Create: `src/synth.js`
- Test: `test/synth.test.js`

**Interfaces:**
- Consumes: `CONFIG`
- Produces:

  - `createSynth(ctx: AudioContext)` returns `{ pluck(freq, velocity): void }` (browser only, not unit-tested). It caches one `AudioBuffer` per frequency. Each pluck is a new `AudioBufferSourceNode` → `GainNode` (gain = velocity) → `ctx.destination`.

  - All samples are within [-1, 1].
  - Decay: the RMS of the window from `decayS` to `decayS+0.1` s is between 0.2 and 0.6 times the RMS of the first 0.1 s. Check this at 220 Hz. It ensures the sound matches the visual decay.
  - Pitch: for 220 Hz, the autocorrelation over samples 4800–9600 peaks at a lag within ±2 of `48000/220` among lags 150..300.

- [ ] **Step 2:** Run `node --test test/synth.test.js`. Expected: FAIL.
- [ ] **Step 3:** Implement. Use a delay line of length `N = round(sampleRate / freq)`, filled with `random()*2-1`. ### Task 7: Browser app: tracker, renderer, main loop, page

**Files:**
- Create: `index.html`, `styles.css`, `src/tracker.js`, `src/render.js`, `src/main.js`, `README.md`

**Interfaces:**
- Consumes everything above.
- Produces:
  - `createTracker(video: HTMLVideoElement): Promise<{ detect(now: number): Frame }>`
    - Uses `HandLandmarker` from `https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@0.10.14`, with wasm from the same package at `/wasm`.
    - Model: `https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/1/hand_landmarker.task`
    - Options: `delegate: 'GPU'`, `runningMode: 'VIDEO'`, `numHands: 2`.
    - Each frame is converted to mirrored window pixels and passed through `smoothHands`.
    - `label` comes from `handedness[i][0].categoryName`.
  - `render(ctx, { strings, preview, hands, pinched, now })`. Draws each string as a polyline of 40 segments offset along its normal by `displacement`. Line width is 3 and color is `str.color`. Glow uses `shadowBlur = 20*glow`. When `deleteProgress > 0`, the color is interpolated toward red. The preview is a dashed line. Hand markers: a dot at the index tip, and a ring at the pinch point when pinched.
  - `main.js` runs this loop on each `requestAnimationFrame`:
    1. `frame = tracker.detect(now)`
    2. `events = engine.update(frame, strings)`
    3. apply the events:
       - `create` pushes `createString(a, b, frame.t, hypot(width, height))`
       - `pluck` calls `pluckString` and `synth.pluck(freq, velocity)`
       - `deleteProgress` sets the string's `deleteProgress`
       - `delete` removes the string
       - `preview` / `previewEnd` set or clear `preview`
    4. `render`
    5. `debug.update(frame, engine, strings)`, once Task 8 exists. Until then, leave a no-op call site guarded by `if (debug)`.

### Task 8: Debug overlay, recorder and replay script

**Files:**
- Create: `src/debug.js`, `scripts/replay.js`
- Modify: `src/main.js` (create the debug object and wire the keys), `index.html` (`<pre id="debug">`)
- Test: `test/replay.test.js`

**Interfaces:**
- Consumes: `createGestureEngine`, `createString`, `pinchRatio`, `isOpenPalm`
- Produces:
  - `createDebug(preEl)` returns `{ update(frame, engine, strings), toggleOverlay(), toggleRecording() }`
    - **Overlay (`D`):** shows FPS, `engine.state`, string count, and per hand its label, `pinchRatio` to 2 decimals, and `isOpenPalm`.
    - **Recorder (`R`):** while recording, a red "● REC" shows top-right, and frames are collected. Pressing `R` again downloads `air-harp-<timestamp>.json` with the content `{ width, height, frames: Frame[] }`.
  - `runRecording(recording, cfg = CONFIG): GestureEvent[]`, exported from `scripts/replay.js`. It replays the frames through a fresh engine and applies `create`/`delete` to a local strings array, so plucks and deletes behave as they did live. Every returned event has `t` added.
  - Running `node scripts/replay.js <file>` prints one line per event, e.g. `1234ms pluck id=2 v=0.63`.
